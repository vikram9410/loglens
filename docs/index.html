Installation

~30 seconds. No API key. No clone. No config files.

Requirements

  • ✓ VS Code 1.85+ or Cursor (VS Code fork)
  • ✓ One MCP-aware AI client installed: Claude Code, GitHub Copilot Chat, or Cursor's built-in AI
  • ✓ Node.js 18+ on PATH (used to spawn the MCP server)

LogLens auto-writes the MCP config to all three client locations (.mcp.json, .vscode/mcp.json, .cursor/mcp.json) on Setup — works with whichever you have or install later.

1

Search "LogLens" in VS Code Marketplace

In VS Code, open the Extensions panel (Ctrl+Shift+X on Windows/Linux, Cmd+Shift+X on Mac), type LogLens in the search box, then click Install on our listing.

Look for the LogLens icon (gradient magnifying glass) published by LogLens AI — that's us.

2

Open your service repo in VS Code

LogLens activates and shows a notification:

11 MCP tools exposed to Claude Code

All tools available in any Claude Code chat. No setup beyond the one-click install.

list_issue_analyses

List issue categories (api-errors, auth-failures, etc.). Handles monorepos by grouping issues per repo.

get_general_context

Load repo overview: service description, correlation keys, modules, noise filters.

get_issue_analysis

Full schema for one issue: error patterns, playbooks, related fields.

start_investigation

3-step guided flow: description → ID prompt → Loki queries + playbook.

analyze_logs

Pattern-match raw log text against known error patterns. No LLM call.

scan_codebase_for_loggers

Walk the codebase, detect logger libraries, sample error messages — feeds AI schema generation.

get_schema_template

Return exact required JSON shape with valid examples — for AI to follow before writing files.

validate_schema

Dry-run validate a JSON string before writing to disk. Returns ✅ or specific errors.

propose_schema_updates

Diff your codebase vs current schemas. Suggests new issues, modules, and patterns to add.

list_module_files

Return file list + structural excerpts for a folder. Powers module Q&A.

reload_schemas

Force re-read of all schema files. Includes folder inspection + validation errors on failure.

Schema structure

Plain JSON. Lives in your repo. Easy to review in PRs.

Folder layout

.loganalysis/
├── manifest.json ← Index
├── general-context-schema.json ← Service overview

├── auth-errors-analysis-schema.json
├── database-errors-analysis-schema.json
└── ...

{
  "repo": "my-service",
  "issueAnalyses": [
    {
      "id": "api-errors",
      "file": "api-errors-analysis-schema.json",

    }

}

FAQ

Do I need an Anthropic or OpenAI API key? ▶

No. LogLens uses Claude Code's own LLM via MCP. As long as you're logged into Claude Code, you're good. Zero per-token cost from LogLens.

What if I don't use Claude Code? ▶

LogLens works with three clients today: Claude Code (reads .mcp.json), GitHub Copilot Chat (reads .vscode/mcp.json), and Cursor's built-in AI (reads .cursor/mcp.json). Setup writes all three on your behalf.

How is this different from generic AI debugging? ▶

Generic AI gets your error message and improvises. LogLens gives Claude your codified domain knowledge — module names, correlation IDs, known error patterns with root causes, playbooks. Less hallucination, more deterministic flows.

Do schemas live in my repo? What about privacy? ▶

Schemas are plain JSON in .loganalysis/. Commit them to your repo so teammates inherit. The extension makes zero outbound network calls. Claude Code controls all data flow under its existing trust boundary.

How do schemas evolve with my code? ▶

After a release, run propose_schema_updates in chat. Claude diffs your code vs the schemas and proposes additions. Review, commit, ship. Teammates get the update via git pull.

Does it work with my logging library? ▶

Yes. scan_codebase_for_loggers auto-detects winston, pino, log4js, @tsed/logger, bunyan, slf4j, Python logging, Go zap, logrus, and more. Schemas are framework-agnostic — they just describe your modules and error patterns.

Can teammates use schemas without installing LogLens? ▶

Each teammate installs LogLens (one-click from Marketplace). They click "Setup" once → done. They never need to author schemas — those are inherited via git.

What happens during incidents? ▶

Open Claude Code → describe the symptom → LogLens guides you to the right ID → returns the exact Loki query → matches incoming logs to known patterns → suggests next steps. Triage in seconds, not hours.
